## 2. Core Components

### 2.1. Live Telemetry Console (`app/live/page.tsx`)
- **Purpose:** Central command center for active Grand Prix weekends.
- **Session Timetable:** Displays the 4 competitive sessions (`Sprint Qualifying`, `Sprint Race`, `Qualifying`, `Grand Prix`) with dates, start times, and real-time status badges (`LIVE NOW`, `UPCOMING`, `CONCLUDED`, `NOT SCHEDULED`).
- **Timing Classification Tower:** Displays driver positions, numbers, team color indicators, gaps, intervals, sector benchmarks, speed traps, Pirelli compound badges, tyre age, and pit counts.
- **Mission Control Feed:** Auto-scrolling terminal capturing genuine FIA Race Control notices, flag condition changes (`GREEN`, `YELLOW`, `SAFETY CAR`, `RED FLAG`), and pit-wall uplink status.

### 2.2. Interactive Circuit Radar (`app/components/CircuitMap.tsx` & `app/lib/circuitTransform.ts`)
- **Coverage:** 78 Formula 1 circuits (25 current calendar tracks + 53 historic circuits) spanning 4,348 corners.
- **Geometry Pipeline:**
  - `computeTransformBounds`: Determines bounding boxes, normalizes scale, and applies coordinate orientation rules (`invertY: true` for FastF1 Cartesian coords; `invertY: false` for screen-space registry paths).
  - `transformCorners`: Implements a 5-pass iterative collision relaxation algorithm (`MIN_LABEL_DISTANCE = 38px`) to prevent badge collisions in tight chicanes (e.g. Monza T1–2, T4–5).
  - SVG Anchor Stability: Prevents hover jitter by strictly avoiding `transformOrigin: center` on dynamic translated nodes.
  - High-Density Centerline Fallback: Always falls back to `getTrackDefinition(circuitId).path` (200+ smooth points) rather than raw corner apex connections.

### 2.3. Paddock Race Predictor (`app/predictor/`, `app/lib/racePredictorService.ts`, `app/lib/raceResultsService.ts`)
- **Purpose:** Rigorous machine-learning winner forecast engine strictly anchored to verified post-qualifying telemetry.
- **Strict Pre-Qualifying State Gating:** Zero mock simulations. If Saturday qualifying has not concluded (or official session data is unverified), the UI locks into a clean `Qualifying Not Yet Completed` countdown screen.
- **2026 Grid Calibration:** Incorporates active team transfers (e.g. Hamilton to Ferrari, Sainz to Williams, Hulkenberg & Bortoleto to Sauber/Audi) with realistic aerodynamic constructor index weighting.
- **Immutable Accuracy Audit Ledger:** Tracks predictions vs. actual race finishes initiated from this Grand Prix onwards. Persists immutable snapshots to Supabase and verifies official podium finishes via Jolpica/Ergast.
- **Responsive Layout Architecture:**
  - *Mobile (< 1024px):* Streamlined vertical layout placing top driver rankings prominently on the primary screen without horizontal table clipping.
  - *Desktop (≥ 1024px):* Multi-column telemetry dashboard with side-by-side probability breakdown and telemetry explanation matrix.

### 2.4. Telemetry Proxy Daemon (`scripts/f1-proxy.js`)
- **Port:** Local WebSocket server on `ws://localhost:8080`.
- **Protocol:** HTTP POST negotiation with `livetiming.formula1.com/signalrcore/negotiate`, WebSocket tunnel connection, and raw Base64/Gzip decompression.
- **Data Channels:** Relays `TimingData`, `DriverList`, `TimingAppData`, `TrackStatus`, `RaceControlMessages`, `SessionInfo`, and `WeatherData`.

### 2.5. Authentication & Personalization (`app/lib/jwt.ts` & `app/components/AuthGate.tsx`)
- **Auth Provider:** Supabase Auth with PKCE flow and Google OAuth 2.0.
- **PostgREST Security Compliance:** Explicit database role grants (`anon`, `authenticated`, `service_role`) paired with strict Row Level Security (RLS) policies.
- **Session Security:** Web Crypto HS256 JWT tokens persisted in `HttpOnly; Secure; SameSite=Lax` cookies (`paddock_auth_token`), preventing client-side script inspection.
- **Constructor Themes:** Dynamic CSS variable injection supporting all 10 constructor palettes and high-resolution pit-wall wallpapers.

### 2.6. Strategy & Pit-Wall Telemetry Lab (`app/lab/page.tsx` & `app/lab/components/`)
- **Purpose:** Engineering command deck for deep sector telemetry dissection, head-to-head tactical strategy simulation, and non-linear Pirelli tire degradation physics.
- **Circuit DNA & Sector Domination Matrix (`CircuitDNASectorMatrix.tsx`):**
  - Ingests empirical official session timing and speed trap telemetry from the FIA Jolpica archive.
  - Decomposes laps into Sector 1 (aero downforce), Sector 2 (mechanical traction), and Sector 3 (DRS straight-line efficiency).
  - Calculates the **Theoretical Ultimate Lap** (Purple S1 + Purple S2 + Purple S3) against the actual pole position benchmark.
- **Tyre Degradation Lab (`TyreDegradationLab.tsx`):**
  - Segment clean laps into Stint 1, 2, and 3 with fuel-burnoff compensation ($+0.055\text{s/lap}$).
  - Scores drivers on the **Tyre Whisperer Index (0–100)** and models Pirelli's 3-Phase thermal degradation curve.

### 2.7. Race Replay Workstation (`app/replay/page.tsx` & `app/components/replay/`)
- **Purpose:** Interactive full-distance race replay console with multi-driver tracking, lap-by-lap classification, and event feeds.
- **Circuit Replay Engine (`CircuitReplay.tsx`):**
  - Renders 2D circuit map with official timing sectors (S1 Cyan, S2 Gold, S3 Magenta).
  - Starting grid staging positions all 20 cars along the start/finish straight tangent vector in a clean 2x2 grid with smooth launch acceleration.
  - Isolated track gate lines rotate across the straight while label badges (`FINISH`, `S1 SPLIT`, `S2 SPLIT`) remain upright.
  - Smooth 60fps driver pack interpolation along high-density centerline track coordinates with pass-phase overtake transitions.

## 3. Data Flow & Integration Points

1. **Calendar & Track Initialization:**
   - On mount, `loadCalendar()` fetches `${API_BASE}/current.json`.
   - Resolves active Grand Prix and synchronizes 4 competitive session timetables.
2. **Race Prediction Request Pipeline:**
   - Client requests `/api/predictions/race/[raceId]`.
   - Handler queries memory cache $\to$ disk snapshots $\to$ Supabase snapshots.
   - If missing, validates qualifying completion before calculating feature vectors.
   - Generates predictions with sha256 input hash and saves immutable audit record.
3. **Bandwidth & Static Asset Delivery:**
   - Next.js edge configuration in `next.config.ts` enforces `compress: true` (Brotli/Gzip).
   - Serves `/data/:path*` and `/images/:path*` with `Cache-Control: public, max-age=31536000, immutable`, eliminating redundant bandwidth transfer on repeated navigations.

## 4. Technical Debt & Conventions

### 4.1. Conventions
- **Language & Runtime:** TypeScript 5 in strict mode. Next.js App Router with React 19.
- **CSS & Theming:** CSS custom properties defined in `app/globals.css` (`var(--carbon-1)`, `var(--line)`, `var(--red)`, `var(--cyan)`).
- **Network Resilience:** All API calls use hardened `getJSON()` in `app/utils/api.ts` with empty-body detection, 3-stage exponential backoff, and user-friendly error normalization.
- **Testing Standard:** Unit, integration, and benchmark tests run via Vitest (`npm test`). All core calculation logic must maintain 100% test passing status.
